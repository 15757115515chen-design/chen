# 赛前足球赔率分析

先读 `references/sources.md` 确定可实际获取的数据与来源限制，再按 `references/data_contract.md` 建立无赛果输入。已有规范化截面时，可在**独立的工作目录**运行 `scripts/analyze_packet.py` 生成概率；评分前先封存规则、输入、预测和散列。抓取原网页可使用 `scripts/capture_titan.py` 留痕，但网页捕获**不自动等于盘口解析或数据合格**。若用户要评估或 ROI，再读 `references/evaluation.md`。

## 何时使用

用户要求分析未开赛足球比赛的欧赔、亚盘、必发交易所或基本面，或要求按历史赛前信息回放、比较预测规则时使用。先确定分析对象、市场（默认全场 1X2）、决策时点、可用来源和输出用途。对已经结束的比赛，明确称为“历史盲回放”；只有事先保存了不可修改的赛前输入和预测，才称前瞻性盲测。盘口解读是待检验的假设，不据价格走势推断庄家动机、真实受注额或必然赛果。

## 输入清单

**必需：** 可唯一匹配的比赛标识、主客方向、联赛、带时区的已知开球时间；至少两家有来源和原始报价时刻的完整赛前 1X2 主/平/客十进制赔率，以及公司和非滚球状态。若需评估，还要有与预测输入物理隔离的最终赛果。少于两家合格 1X2 时，脚本弃判；单家公司去水概率仅可作为不出预测的参考数据，不用其他盘口凑出三项概率。

**可选：** 同公司逐笔亚盘及欧赔、开球前 24 小时可核实的参照报价；已在 `T` 前公开的上赛季完整统计、逐场重建的本季战绩和有正文版本的队讯；在 `T` 前有可信快照的必发已撮合量价；用于 ROI 的真实可成交赔率、手续费和下注限额。可选资料缺失只关闭对应信号，不应减少市场基线的样本覆盖。

## 固定时点并隔离赛果

1. 每场记录赛事 ID、主客队、联赛、官方开球时间及其时区。默认决策时点 `T = 开球时间 − 60 分钟`，本包 `prepare_packet.py` 和 `analyze_packet.py` 只支持此预测时点（另制备 T−24h/T−3h 作辅助截面）。若用户指定另一时点，先记录该时点，另行冻结相应截面与分析规则并人工分析或修改脚本再检验；不能把本包 T−1h 输出标为别的时点。所有时刻转成带时区的 UTC 比较；夏令时、推迟开球和来源时间不明时先核实，无法核实则停用相应记录。
2. 把赛果、比分、赛后技术统计、滚球和 `T` 后的赔率放在预测输入之外。通过字段白名单读取比赛标识、合格报价及已公布的背景资料；禁止把整张含比分的表直接连接进特征。历史样本的赛果只可作为其结果在目标场 `T` 前已公布的训练资料，不能成为同一场的赛前特征。
3. 每条资料留存来源、原始记录、报价或内容版本时刻、抓取时刻及准入判断。逐笔报价须满足 `quote_time ≤ T`，属于目标场、正确市场、明确公司且不是滚球或赛后记录。预生成的“初盘”“终盘”“开赛前最后一笔”均要回查原始时刻；“开赛前”不等于 `T` 前。赛后归档网页即使显示历史报价时间，也只能支持有局限的回放，不能单凭网页现状证明当时确实可见。
4. 队讯需要能核查的发表、修改及正文版本，均不晚于 `T`；预测首发不是确认首发。当前赛季战绩仅纳入其终场结果已在 `T` 前公布的比赛。无时间的收盘赔率、后来更新的网页正文、全程覆盖汇总及目标场结果不得补缺。

## 建立 1X2 市场基线

1. 本包脚本默认以 Titan 页面 ID `1、8、9、14` 四家公司为基线公司集合，用于复现既有回放；若扩展公司，必须在新比赛赛果可见前修改并封存代码与集合。对每家公司，在 `T` 前逐笔记录中选最新一组三项完整十进制赔率，默认丢弃距 `T` 超过 72 小时的报价。公司身份要有证据；遮盖名保留为遮盖名，不能仅凭赔率接近就合并。每家公司只占一票，不因更新次数多而增加权重。
2. 对公司 `c` 的主、平、客结果 `i∈{1,X,2}`，计算 `q[c,i]=1/odds[c,i]` 与去水概率 `r[c,i]=q[c,i]/Σ_j q[c,j]`。逐项取公司间中位数 `m[i]=median_c r[c,i]`，再令 `p0[i]=m[i]/Σ_j m[j]`。同时记录公司数、最老报价年龄及各公司原始赔率的水分 `Σ_j q[c,j]−1`。同一时点的市场共识 `p0` 是所有附加规则的对照基线。
3. 报出 `p0(1/X/2)`、最大概率及概率最大的选择；精确并列时预先规定按 `1、X、2` 排序。最大概率表示该模型的赛果不确定性，不能把它称为命中保证。
4. 证据质量可固定为：A＝至少三家公司报价年龄不超过 24 小时；B＝否则至少两家公司不超过 72 小时；其余为 C。若任一结果的公司间去水概率极差超过 5 个百分点，或出现下述欧亚冲突，每项降一级，最低 C。质量只描述资料完整度与一致性，不代表经验命中率。

## 审慎处理基本面、亚盘和必发

**基本面。** 可以列出来源可追溯的上赛季每场积分、升降级、赛程密度、已确认伤停与 `T` 前已结束比赛的近期状态；同联赛、同口径比较，并说明升班马或缺失资料。不要把旧赛季积分差直接当成当季胜率。若要复现既有的研究候选规则，事前写明：仅双方上季都在本场顶级联赛、每场积分差绝对值至少 `0.60`，且上季强弱方向与 `p0[1]−p0[2]` 相反时，从市场占优一方的胜率移 `0.01` 给上季较强一方，平局不动；其余 `p_candidate=p0`。该 1 个百分点只是待验证的有限修正，默认报告基线与候选值，不把它宣称为已证实的预测改进。其他基本面只作有出处的注释；若需数值修正，须在新样本赛果可见前固定公式和上限。

**亚盘与欧赔。** 只比较同公司、同一 `T` 截面，并以**开球前 24 小时**可见的最近合格报价作走势参照；没有参照则不判走势。欧赔以去水后主胜减客胜概率的变化衡量方向，可预设 `0.02` 为显著阈值；亚盘以主让球线变化至少 `0.25` 球，或盘口线不变而一方水位下降至少 `0.05`，作为方向证据。不同盘口线的水位不能直接相比。至少两家公司欧赔方向相同、对应亚盘方向相反时记“欧亚冲突”，降低证据质量并解释分歧；这类走势已部分进入 `p0`，不重复叠加概率修正。跨公司展示去水概率、返还率、报价年龄与可证实的先后顺序，不从原始低赔或调盘臆测资金流向。

**必发交易所。** 只有取得同场全场胜平负市场、在 `T` 前可核实的**已撮合**成交价与成交量，且区分挂单量与成交量时，才可计算三项量价份额：`BF[i]=100×V[i]×O[i]/Σ_j(V[j]×O[j])`。标注其口径是交易所成交数据；它既不是博彩公司受注额，也不是赔付负债。交易所赔率本身不能替代成交量。第三方归档若只有自称的冻结时间而无独立快照，列为待核线索，不进入严格赛前特征；缺失量价时明确写“必发信号不可用”。任何由必发信号驱动的概率或下注规则，都须先冻结并单独检验。

## 弃判与单场交付

少于两家合格的完整 1X2 报价时，停止本模型概率预测并写明原因，不能用事后收盘价补齐。仅一家报价可单列该公司去水赔率作为参考，但不生成 `p0` 或模型选项。关键时间戳不可靠或来源冲突无法解释时也弃判。缺少可执行价格时不提供投注建议。信号不足本身是结果，不填零、不把未知写成中性证据。除非已有独立样本校准过下注规则，默认只给概率和证据，不把正向盘口注释直接转成下注指令。

每场按同一格式交付：`比赛与 T → 来源及报价年龄 → 各公司合格 1X2/AH/BF 截面 → p0 与事前定义的候选概率 → 1/X/2 选择和质量等级 → 基本面/欧亚/必发证据及缺失 → 弃判理由或可执行赔率与已固定的投注规则`。清楚区分观察事实、计算结果和解释性假设。

## 冻结、盲评与收益核算

批量评估前固定比赛清单、输入列、时间门槛、公式、阈值、弃判条件、投注规则和代码版本。先输出不含比分的逐场预测与文件 SHA-256，再开放独立的结果表；回放时尽可能让预测执行者无法读取目标赛果或联网查询。将预测生成时间、资料快照来源和解盲时间写入记录。本地时间戳与哈希可检验文件一致性，但不是第三方可信时间证明。赛后改规则属于新实验，不能重报为原盲评。

评估需报告总场数、覆盖与弃判、最高概率项命中率、三分类 Brier（每场 `Σ_i(p[i]−y[i])²` 的均值）及 log loss（真实结果概率的负自然对数均值）。在**同一可预测比赛集合**上成对比较 `p0` 与候选模型，说明样本数和不确定性。若用户要求收益率，必须先冻结下注触发条件、候选公司、`T` 前确实可成交的赔率、手续费、限额、固定或预定的下注额、平局/退回/走盘结算规则；收益率为净盈亏除以实际下注本金。无有效下注时收益率记为“不适用”，不能记成零。没有可核实成交价或规则未事先冻结时，不计算可归因于策略的 ROI；赛后最优赔率只可作诊断，不可假设当时能买到。

既有 40 场五大联赛回顾性盲回放是本流程的适用边界：市场基线与书启发的候选修正均覆盖 40/40、最高概率项均命中 25/40（62.5%）；基线与候选的平均 log loss 分别为 `0.88746`、`0.88806`，三分类 Brier 分别为 `0.51786`、`0.51831`。候选规则只触发一次，未显示相对同期赔率基线的增量提升，也不足以判断长期有效性。该回放使用赛后归档的历史报价时间，缺少不可修改的当时网页快照；未来应在赛前自动留存原文与抓取时间，并扩大真正样本外验证。不得声称能保证盈利。

## 文件与脚本的用法

`scripts/capture_titan.py` 只保存赛程已核对比赛 ID 对应的原始页面、下载完成的 UTC 时刻、最终 URL 和散列；页面字段须依 `references/sources.md` 人工或经另行验证的解析器转成 `raw_quotes.csv`。`scripts/prepare_packet.py` 将其按开球前 24/3/1 小时截断，生成无赛果的 `market_asof.csv`，并把来源链接另存审计目录。默认严格模式需要 `--capture-manifest`，逐条核对 `raw_quotes.csv` 与留存原页的 ID、市场、公司、URL、抓取时刻及散列，并要求声明解析版本和时区依据；这一机械核对不能证明解析语义正确，须抽样回查原页。仅使用赛后归档时显式加 `--historical-replay`，在报告中降级为回顾性回放。`fixtures.csv` 与 `prior_season.csv` 依 `references/data_contract.md` 单独准备。第三方给出的整理后 CSV 也必须逐行复验，不能以文件名中的“赛前”作为准入证据。

以下命令在本 Skill 目录执行，并把示例路径替换成实际文件路径；`capture_早/晚` 指采集器新建的两个不同目录。分别在 T−24h 与 T−1h 截点**之前**完成原页抓取，才能严格证明对应截面当时可见；应给下载预留时间。若只分析最新 T−1h 截面，可只保留晚一次采集及一个 `--capture-manifest`。

```bash
python scripts/capture_titan.py --fixtures /path/to/fixtures.csv --out-dir /path/to/captures --pages 3in1  # T−24h 前运行
python scripts/capture_titan.py --fixtures /path/to/fixtures.csv --out-dir /path/to/captures --pages 3in1  # T−1h 前运行
# 核对两个采集目录的原页，按 examples/raw_quotes_template.csv 抄录或解析并抽样回查
python scripts/prepare_packet.py --fixtures /path/to/fixtures.csv --raw-quotes /path/to/raw_quotes.csv --capture-manifest /path/to/captures/capture_早/manifest.json --capture-manifest /path/to/captures/capture_晚/manifest.json --out-dir /path/to/prematch_input --audit-dir /path/to/private_audit
cp /path/to/fixtures.csv /path/to/prior_season.csv /path/to/prematch_input/
```

在赛果隔离的工作目录运行：

```bash
python scripts/analyze_packet.py --input-dir /path/to/prematch_input --output-dir /path/to/locked_forecast
```

脚本复现上面的 1X2 基线和试验性上季积分修正，同时写出每场证据注释、拒收原因与输入/输出散列。主程序不得读取比分。若源数据不满足规则，按弃判报告；不得用赛后终赔补齐。ROI 的实际交易规则须独立在赛果出现前封存，`references/evaluation.md` 给出结算公式与最小报告格式。

赛后如需评分，可用 `scripts/score_predictions.py --predictions <锁定预测CSV> --results <独立赛果CSV> --out-dir <评分目录>`；若先前固定了公司 ID 和下注规则，可再给 `--bet-quotes <盘口截面CSV> --company-id <ID>` 计算等额投注假设 ROI。未事前固定或无成交记录时，输出必须标为探索性假设收益。
