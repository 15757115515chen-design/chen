# 赛前足球数据获取指南（基于本地已核验样本）

本指南归纳此前 40 场研究中实际用过或核验过的入口和处理方法；文中提到的历史案例文件不随本 Skill 打包，也不是运行本 Skill 的依赖。既有样本是 2026-10-10—11 当地比赛日五大联赛 40 场；覆盖率和可访问性只说明这批比赛，不能推定未来赛程也相同。每条赛前特征都应同时保存**来源声称的事件时间、实际采集时间、数据版本和决策截点**，并检查在决策时是否已可得。

## 1. 比赛清单、ID、开球与赛果

以 `league_code + 当地比赛日期 + 主客队规范名` 建立比赛键，再核对 Titan 的双方、联赛和开球时间，保存独立的 `match_id`。Titan 比赛赔率总页已验证为 `https://op1.titan007.com/Oddslist/{match_id}.htm`；不能仅靠队名猜 ID。此前另一个赛程脚本用过 `https://bf.titan007.com/football/Next_{YYYYMMDD}.htm` 这个**网页**：按 GB18030 解码，从比赛行 `tr` 的 `sid` 属性读取候选 ID，并读取该行的联赛、双方与北京时间。该页面不是经核验的稳定官方 API，结构或可用性可能变化；实际采集后仍须逐场打开赔率总页核对 ID、主客和开球。也可使用有授权的赛程源取得候选 ID。注意当地比赛日与北京时间日期可能不同，不能以北京时间日期直接连接 Football-Data 的 `Date`。

这批赛果来自固定提交 `5703f4083e084049f0cb3292c26008b8e353915b` 的 [Football-Data 2026/27 五联赛镜像](https://github.com/Patzaza81/archetype-foot/tree/5703f4083e084049f0cb3292c26008b8e353915b/data/football_data/raw/2627)，文件路径为 `.../2627/{E0,SP1,D1,I1,F1}.csv`。源字段 `Div,Date,Time,HomeTeam,AwayTeam,FTHG,FTAG,FTR` 分别提供联赛、当地比赛日期、源文本时间、双方、全场比分及 H/D/A 赛果；按联赛、日期、双方一对一连接后，再核对比分。`Time` 的源时区未获明确说明，Titan 的北京时间应由其比赛页独立核对。比分和终场结果只能在赛后作为标签，不能从事后 CSV 回填为赛前状态；未来赛程的实时发布与最终结算时刻也没有在此项目中验证。

## 2. Titan 逐次盘口：可复核的页面路径

从上述总页点「亚让」或「进球数」列表，再点所需公司行的「详」。本项目核验了下列全场历史详情路径；`id` 是 Titan 比赛 ID，`companyID/companyid` 是该入口使用的公司 ID，`l=0` 为简体、`l=1` 为繁体。实际解析须记录最终打开的 URL，不能仅记录模板：

| 内容 | 已用页面模板 | 提取字段 |
| --- | --- | --- |
| 亚洲让球逐次 | `https://vip.titan007.com/changeDetail/handicap.aspx?companyID={company_id}&id={match_id}&l=0` | 主客香港水位、让球原文、状态、月日时分 |
| 胜平负逐次 | `https://vip.titan007.com/changeDetail/1x2.aspx?companyid={company_id}&id={match_id}&l=0` | 主/平/客十进制赔率、状态、月日时分 |
| 全场大小球逐次 | `https://vip.titan007.com/changeDetail/overunder.aspx?companyid={company_id}&id={match_id}&l=0` | 大小两侧香港水位、总进球线、状态、月日时分 |
| 三合一逐次 | `https://vip.titan007.com/changeDetail/3in1Odds.aspx?companyid={company_id}&id={match_id}&l=0` | 分区读取亚盘、大小球、胜平负 |

原有 40 场使用页面显示 `36*`/ID 8；多公司样本还核验了 `澳*`/ID 1、`威*`/ID 9、`伟*`/ID 14、`利*`/ID 31。**保留页面遮盖名和 ID，不把 `36*` 擅自写成 Bet365；`利*`/31 是利记/SBOBET，不是立博/Ladbrokes。** 不同入口的公司编号体系也不能混用。有关立博的 `1x2d.titan007.com/{match_id}.js` 动态源和 `OddsHistory.aspx` 不透明记录 ID，在本批比赛尚未完成验证，不能当作可用接口。

既有采集使用网页渲染行号分窗读到页尾，保留 `source_url`、`source_line`、原始行及抓取工具的 `Crawled` 标记。三合一的一条变价常分成相邻两行：一行是赔率/盘口和月日，下一行是时分与 `即/早/滚` 状态；按市场分区、相邻行和页面由新到旧的顺序合并。同一分钟可有多次变化，较小的页面行号更靠近最新，不能仅按分钟去重。详情页和三合一页可能是不同缓存版本；本地实例中三合一含更晚的记录，多公司亚盘重抓又使 20 页补出更晚报价。本包不附历史抓取脚本；解析时须直接核对已保存的原始网页。

报价页的月日时分无独立年份与时区标识：样本按比赛页所示北京时间（`Asia/Shanghai`）解释，并以赛程年份补全年份，跨年赛程需单独处理。只允许可辨识的赛前状态 `即`、`早`、`初盘/(初盘)` 且 `quote_time < kickoff_time`；排除 `滚`、开球同分钟或之后、及时间/盘口无法解析的行。`l=0` 报 502 时曾有 `l=1`、单项页或三合一页可用，也有始终失败的场次；失败应写明 HTTP/导航/解析原因，不能等同公司未开盘。保存每条的市场、公司 ID、盘口线原文、标准化值、赔率格式和原页面定位。亚盘标准值是**加到主队进球上的补偿**（主让半球 `-0.5`，主受让半球 `+0.5`）；大小球 `2.5/3` 为 `2.75`；香港水位转十进制赔率需加 1。不同盘口线的两侧水位不可直接比较。

按比赛×公司×市场建立覆盖表，列出抓取状态、可见行数、最早和最后严格赛前报价、最新报价距开球分钟数及缓存标记。时点截面（例如 T−3h、T−1h）从**截点以前**可见记录取最后一条，并同时输出 `quote_age_minutes`；不存在则留空。最早可见值只是 `first_visible`，除非单项页明确标 `初盘`，也仅能称“页面标记初盘”；末条可见变价不能自动称可交易封盘。亚盘聚合表的静态“终”与详情最后赛前价在本地仅 120/135 项一致，不能代替带时间戳的记录。原有 40 场 120 个市场中仅 92 个的末次变价落在开球前 10 分钟；报价年龄是必要质量字段。所有缺口保留为空，不能用别家公司或赛后收盘价填充。

## 3. 补充结果、历史实力、近期状态及队讯

可复用 [Football-Data 的赛季 CSV](https://football-data.co.uk/downloadm.php) 做已完成比赛、历史 1X2 与较早/收盘两组赔率。本地历史库固定了 `Char2mant/futbol-veri-aynasi` 提交 `178ea3f8d54f69d9d73092f213c6e18b26b95b81` 下 `data/fd/{season}/{league}.csv`，记录逐文件 SHA-256、编码、赛季及公司字段覆盖；从所述固定提交逐文件下载并记录 SHA-256 后可自行重建。`B365H/D/A` 与 `B365CH/CD/CA` 等不带/带 `C` 代表开市后采样与收盘采样，**均无精确采集时刻**，前者不是首笔初盘，不能构造 T−3h/T−1h。同一文件的 `BFE` 是 Betfair Exchange 赔率，`BFD` 是 Betfred，未知代码（如 `SKB`）保持未核实。`AHh/AHCh` 是市场让球线，`B365AHH/AHA` 是 Bet365 两侧赔率；两者不能合称 Bet365 独家盘口。下载前应另核原站字段定义和使用许可。

上季实力样本来自固定提交 `e6744429ee395bc86f247348c6184bb08d4eb361` 的 `openfootball/football.json/2025-26/{en,es,de,it,fr}.{1,2}.json`，并对不全的次级联赛及官方排名/判罚用公开最终表补正。应排除升级附加赛，按完整赛果算胜平负、积分和得失球，保存来源 URL、SHA-256 及 `rank_basis`；不完整比分不能推出最终名次。次级联赛覆盖率须逐赛季核对。当前赛季近期状态必须由在目标场决策时点之前**已公布最终结果**的联赛比赛逐场计算。此前案例脚本只要求历史场次的计划开球比目标场早 150 分钟，在目标场开球前 1 小时决策时，可能把仅开赛 90 分钟的前场比赛算进去，因此该汇总已从严格盲测输入剔除。未来必须用实际终场和结果公布时间核验；不足六场就保留实际 `last6_n`，不补造尚未发生的比赛。

赛前伤停与预计阵容是逐篇带来源的文本证据。本地英超采用赛前发布的 Guardian 队讯，其他四联赛采用对应赛前文章及官方/媒体预览，覆盖清单记录文章 URL、页面显示的发表/修改时间、双方、人数定义与限制。抓取时应存不可变正文快照及抓取时间，区分确定缺阵、存疑、恢复中、停赛和预测首发；同一人跨类别不能简单相加。既有页面有赛后比分和静默更新，因此仅“文章日期早于开球”不足以证明当前正文是当时已知信息；没有可信历史版本时应标 `prematch_version_unverified`，不得把当前名单直接当冻结赛前特征。预测首发也不能写成确认首发。

## 4. Betfair 成交量与替代来源

此前本地研究验证：Football-Data 的 `BFE/BFEC` 只有交易所**赔率**，没有成交量；Titan 数据产品页声称提供约五分钟更新的必发量价，但本批没有可核验历史快照的公开接口。90qu 日期归档在 40 场里覆盖 35 场，主/平/客成交量与网页总量一致，`100×V_i×O_i / Σ(V_j×O_j)` 可重现其“必指”（最大差 0.049 个百分点）。然而网页宣称的赛前定稿时间没有独立审计，不能进入严格赛前回测；另 5 场保持缺失。交易所成交量只是该市场资金流代理，不能当成各博彩公司受注量或风险敞口。

若需要可核验的 Betfair 历史成交量，需注册 [Betfair 历史数据服务](https://historicdata.betfair.com/)并获取付费 Advanced/Pro 足球 `MATCH_ODDS` 文件；免费 Basic 是分钟末次成交价、**不含成交量**。以 `publishTime < 实际开球 UTC` 及赛前市场状态过滤，再计算目标截点。Pro 的 `trd` 表示各价格的累计成交量，需要按价格状态重建，不能逐条简单求和；历史资料据现有审计说明在结算后约五天才可取得。另一个付费选项 [The Odds API 历史接口](https://the-odds-api.com/historical-odds-data/)提供约五分钟间隔的历史快照，但本环境无凭据，本批具体公司/亚盘覆盖未经验证。两者的订阅、授权和时效需在实际接入时另行确认。

## 5. 抓取边界与记录契约

现有文件没有核验 Titan 的官方请求频率上限，也没有证明可从 shell 直接自动下载这些详情页；曾有 HTTP 502、403/工具不可访问和缓存差异。本包 `capture_titan.py` 是单次、固定间隔的原页留存工具：它记录失败，不会对 429/5xx 自动重试、退避或复用缓存。因此要遵守实际站点许可与访问限制，遇失败须人工核查，不能把抓取失败写作赔率缺失。若扩展成长期采集器，再加入适当退避、重试、缓存及其记录。每次采集最好保存原始响应/渲染文本、最终 URL、HTTP/工具状态、下载完成 UTC、页面声称时间、SHA-256、解析版本和原行定位；这些是可审计采集设计，**不是现有 Titan 站点提供的官方限流/API 保证**。Football-Data 免费文件在本地文档中被标为个人或学术使用范围；商业产品、再分发或模型训练应另核原站授权，公开镜像不改变原权利。
